# Схема данных для коллектора

## Формат файла
**JSONL** — один JSON объект на строку, UTF-8.

## Обязательные поля

```json
{
    "video_a": "/absolute/path/to/video_viral.mp4",
    "video_b": "/absolute/path/to/video_average.mp4",
    "views_a": 1500000,
    "views_b": 42000,
    "author_context": "фитнес блогер, продаёт онлайн курс по похудению, аудитория 18-35 женщины, постит 3-4 раза в неделю"
}
```

| Поле | Тип | Описание |
|---|---|---|
| `video_a` | string | Абсолютный путь к первому видео |
| `video_b` | string | Абсолютный путь ко второму видео |
| `views_a` | int | Просмотры video_a |
| `views_b` | int | Просмотры video_b |
| `author_context` | string | Описание автора от агента парсера |

## Важные правила

### Про пары
- **Оба видео от одного автора** — это ключевое условие для чистоты сигнала
- **Разница в просмотрах ≥ 3x** — примеры с меньшей разницей автоматически отфильтровываются (слабый сигнал)
- Примерное соотношение: video_a = вирусное (~топ 20% по просмотрам автора), video_b = среднее
- Порядок A/B можно делать случайным — датасет сам вычисляет label

### Про видео
- Формат: `.mp4`, `.mov` — оба поддерживаются через ffmpeg
- Длина: желательно до 90 секунд (Instagram Reel)
- Аудио: оставляем оригинальное — модель использует `use_audio_in_video=True`
- Разрешение: не ресайзим, процессор сам ресайзит при fps=1

### Про author_context
Агент парсера должен выдавать строку с контекстом:
```
"{ниша}, {что продаёт/монетизирует}, {примерная аудитория}, {частота постов}"
```
Пример: `"кулинария, продаёт рецептурные книги, семьи с детьми, ежедневные посты"`

Это поле будет расширено агентом персонализации в продакшне.

## Пример файла train.jsonl
```jsonl
{"video_a": "/data/videos/user123_viral_001.mp4", "video_b": "/data/videos/user123_avg_003.mp4", "views_a": 2300000, "views_b": 51000, "author_context": "lifestyle, продаёт курсы по медитации, женщины 25-40"}
{"video_a": "/data/videos/user456_avg_012.mp4", "video_b": "/data/videos/user456_viral_007.mp4", "views_a": 38000, "views_b": 890000, "author_context": "бизнес советы, нет продукта, предприниматели 30-50"}
```

## Сплит данных
Рекомендуемое разделение: 90% train / 10% eval.
Важно: в eval не должно быть авторов из train (data leakage через стиль автора).
